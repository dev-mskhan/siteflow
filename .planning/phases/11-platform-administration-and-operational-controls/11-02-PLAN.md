# Plan 11-02: Global organization and account read APIs

## Objective
Permission-controlled, cursor-paginated search and detail views for organizations and accounts, reusing existing services.

## Tasks
1. Routes `/api/v1/platform/organizations` and `/api/v1/platform/accounts` guarded by `requirePlatformPermission('read:organizations')`.
2. Reuse existing organization/account services; no parallel implementation.
3. Expose lifecycle state, owner, membership count, subscription summary (Phase 10 billing service), recent admin audit activity.
4. Accounts: id, masked email, verification, status, membership count. No tokens or credentials.
5. Cursor pagination with max page size; indexed filters only.

## Acceptance criteria
- Bounded page size; EXPLAIN recorded for search queries.
- Org users get 403; no tenant-existence leak via 404/403 differences.
- Swagger/OpenAPI entries added.
